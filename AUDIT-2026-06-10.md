# Treddit Code Audit — 2026-06-10

Scope: security, cost guards, billing, general bugs. Findings below marked **[verified]** were confirmed by reading source; others are subagent findings worth checking.

---

## CRITICAL

### 1. Webhook calls `activateSubscription` with 1 of 4 required args **[verified]**
`app/api/billing/webhook/route.ts:67,93` call `activateSubscription(email)`. Signature (`lib/upstash.ts:159`) requires `(email, subscriptionId, customerId, periodEnd)`.

This ships because `next.config.ts` sets `ignoreBuildErrors: true`. At runtime:
- `subscriptionStatus` is set to `'active'` (so paid access works — why it appears fine)
- `subscriptionId`/`customerId` become `undefined` → dropped by `JSON.stringify` → **you can never match a cancellation webhook to a stored subscription**
- `subsignal:sub-end:{email}` is stored as the literal string `"undefined"` → period-end lookups broken

**Fix:** extract sub ID / customer ID / period end from each provider's payload and pass them.

### 2. `ignoreBuildErrors: true` + `ignoreDuringBuilds: true` **[verified]**
`next.config.ts:5,8`. This is how #1 reached production silently. Remove both (or at minimum run `npx tsc --noEmit` before each deploy).

### 3. `activateSubscription` silently no-ops if user record missing **[verified]**
`lib/upstash.ts:166` — `if (!user) return;`. A payer whose Redis user record doesn't exist (or email case mismatch between Google sign-in and payment payload) pays but never gets activated, with no log. Add a `console.error` + alert email at minimum.

## HIGH

### 4. Razorpay signature check crashes on malformed sig **[verified]**
`webhook/route.ts:23` — `timingSafeEqual` **throws** when buffer lengths differ (e.g. header `x-razorpay-signature: abc`) → unhandled 500. Wrap in try/catch and length-check first.

### 5. Paddle signature comparison not timing-safe **[verified]**
`webhook/route.ts:44` — `computed === h1` is a plain string compare. Use a constant-time comparison like the Razorpay path (post-fix #4).

### 6. No webhook idempotency / event-ID dedupe **[verified pattern]**
Providers redeliver events. Track Paddle `event.id` / Razorpay event id in Redis (7-day EX) and skip already-processed events.

### 7. Cancellation doesn't verify subscription ownership
`webhook/route.ts:70,96` — a signed `subscription.cancelled` naming any email revokes that user. Once #1 is fixed and sub IDs are stored, require incoming sub ID == stored sub ID before cancelling.

### 8. `/api/debug-exa` unauthenticated **[verified]**
Leaks `EXA_API_KEY` prefix/length and fires a real Exa search per hit (open cost faucet, no auth). `debug-env` is already neutered to 404 — do the same to `debug-exa`, or delete both routes.

### 9. Unbounded paid-route rebuilds (cost abuse)
`?rebuild=1` (intelligence-feed), `?refresh=1` (subreddit-directory), new-URL feed builds — each authed request can force a full Haiku+Arctic rebuild. Middleware 15/min + `LLM_DAILY_CAP_USD` bound the blast radius, but one hostile user can still burn the whole daily cap (DoS for everyone else, since the breaker is global). Add a per-user rebuild quota (e.g. 5/day per route).

## MEDIUM

10. **Rate limiting trusts `x-forwarded-for`** (middleware + per-route). On Vercel the leftmost hop is client-influencable. Prefer the platform-set `x-real-ip` / `request.ip`. Also fails open on Redis outage (known trade-off; Vercel WAF rule is the right backstop — confirm it's actually configured).
11. **LLM spend breaker TOCTOU** — concurrent requests can all pass the check before cost is metered; worst-case overshoot ≈ cap + (concurrency × max call cost). Acceptable, but you can shrink it by incrementing a reserved estimate before the call and reconciling after.
12. **Unauthenticated Claude endpoints** — `subreddits-guest`, `post-similar` (anon paths). Bounded by 15/min/IP + daily cap, but same global-cap DoS issue as #9.
13. **Webhook email trust** — email comes from provider payload (`custom_data.user_email` / `notes.user_email`). Safe while signatures hold; storing+matching sub IDs (#1/#7) is the cheap hardening.
14. **Unscheduled cron routes still live** (`build-feeds`, `daily-digest`, `signal-feed`, `weekly-brief`, `morning-brief`, `health-report`) — verify every one checks `CRON_SECRET`; they're internet-reachable.
